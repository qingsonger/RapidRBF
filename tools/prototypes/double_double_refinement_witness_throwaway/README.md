# THROWAWAY PROTOTYPE — double-double refinement witness gate

## Question

Does one exact RapidRBF-owned double-double residual and solution-accumulation
boundary around the unchanged instrumented faer 0.24.4 Bunch–Kaufman factor
and binary64 correction solve close the frozen six-source witness gate on all
four tier-one targets and the `1/12`, `2/12`, and `8/16` profiles?

This is Issue 49 decision evidence, not production solver code. It executes
only ordinals `0`, `36`, `69`, `72`, `106`, and `150`, replays the frozen
unchanged-candidate status vector before refined candidate entry, and keeps
the accepted candidate-independent frozen-system authority and threshold
unchanged.

It does not admit faer, qd, a factor route, or the factor corpus; rerun the
complete Issue 47 cohort; run the mechanism panel; choose persistent factor
storage; enter the 100k rung; or unblock downstream solver comparison.

## Run

The exact four-target gate is dispatched from a pushed branch with:

```text
gh workflow run double-double-refinement-witness.yml --ref <branch>
```

Review a captured cohort non-interactively with:

```text
python tools/prototypes/double_double_refinement_witness_throwaway/tui.py --snapshot <cohort-summary.json>
```

The TUI stores review state only in memory. The only gate dispositions are
`REFINEMENT_ROUTE_SUPPORTED_FOR_FULL_CORPUS_PLAN`,
`REFINEMENT_ROUTE_REJECTED_DIAGNOSTIC_ONLY`, and `INVALID_UNJUDGED`.
