# THROWAWAY PROTOTYPE — controller-valid refinement witness gate

## Question

Does one exact materialization of the accepted sole-waiter/controller repair
validly judge the unchanged double-double refinement witness route on all four
tier-one targets and the frozen `1/12`, `2/12`, and `8/16` profiles?

This is Issue 51 decision evidence, not production solver code. The Rust
candidate, dependencies, feature set, six witness sources, 18 RHS identities,
double-double boundary, thresholds, resource controls, and accepted reference
remain byte-for-byte bound to Issue 49. Only the external controller, verifier,
contract, and workflow change.

The controller launches a fresh Windows Job Object or POSIX process group, uses
one dedicated waiter as the sole terminal/reap authority, samples the complete
subject process tree without polling, and reconciles only one same-handle macOS
root `proc_pidinfo(PROC_PIDTASKINFO)` ESRCH within 1000 ms. Controller invalidity
dominates candidate failure.

It does not admit faer, qd, a factor route, or the factor corpus; run the
mechanism panel; choose persistent factor storage; enter the 100k rung; or
unblock downstream solver comparison.

## Run

The exact four-target gate is dispatched from the pushed throwaway branch:

```text
gh workflow run controller-valid-double-double-refinement-witness.yml --ref codex/execute-controller-valid-refinement-witness
```

Review a captured cohort in one command:

```text
python tools/prototypes/double_double_refinement_witness_throwaway/tui.py <cohort-summary.json>
```

Render the review non-interactively:

```text
python tools/prototypes/double_double_refinement_witness_throwaway/tui.py <cohort-summary.json> --snapshot
```

The TUI stores review state only in memory. The only gate dispositions are
`REFINEMENT_ROUTE_SUPPORTED_FOR_FULL_CORPUS_PLAN`,
`REFINEMENT_ROUTE_REJECTED_DIAGNOSTIC_ONLY`, and `INVALID_UNJUDGED`.
