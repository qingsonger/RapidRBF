# Adopt Wayfinder scope and acceptance governance v2

Accepted: `SOURCE_QUALIFICATION_DEFERRED_TO_IMPLEMENTATION_AND_RELEASE_GATES`.

Wayfinder exists to remove decision uncertainty for `/to-spec`; it does not implement the production solver, build a release-grade evidence system, or perform complete four-platform qualification before specification. The projected strong-admissibility `H2`/IFMM-style approximate-factor route remains the provisional implementation target for mixed-Hermite, strongly globally coupled, and corresponding large-scale workloads, but it is neither an implemented candidate nor a released or qualified route. Specification freezes the mechanism contract, private interfaces, correctness requirements, deterministic routing inputs, resource boundaries, and later qualification gates. Exact source materialization plus 1k/10k/100k and platform qualification move after `/to-spec` and `/to-tickets` into implementation and release work.

The public solver contract is one backend-neutral operation with a versioned, auditable route decision made before execution. Small systems use dense direct solving; compact-support systems use exact-neighbor or sparse solving; qualified ordinary and value-dominated workloads use restarted right-FGMRES with RAS; mixed-Hermite and strongly globally coupled workloads provisionally use the projected hierarchical approximate-factor route. Special ill-conditioned cases either refine explicitly or return stable `AccuracyUnattainable` or `NotConverged`. An observed failure never causes a silent route change, and concrete solver or preconditioner identities do not become stable public API. Each route qualifies only for its declared workload class. Failure to implement or qualify a route blocks the affected v1 workloads until a separately approved alternative passes the same gates; it never weakens a threshold or silently changes the algorithm.

Numerical governance v2 supersedes the single universal interpretation of `NumericalAcceptanceProfile/v1` without rewriting its historical record. `oracle-strict` retains the exact semantics and direct-reference ceilings from Issue 16 for kernels, derivatives, Hessians, small direct solves, and high-precision references. `solver-standard` governs 1k–10k iterative mechanisms: `2^-24` is a value-channel baseline, gradients are independently and candidate-blindly calibrated with an initial `2^-20` hard ceiling, and complete external value/gradient residuals, CPD, and KKT checks remain required. `large-scale` governs 100k–1M using public fit tolerance and requested evaluation accuracy; evaluator, backend, solver, composition, oracle, and rounding error must fit the user tolerance without an unrelated universal `2^-24` veto. No profile may be widened from candidate results.

Platform qualification is role-based. Linux x86_64 with glibc is authoritative for primary numerics, 100k/1M, performance, and resources. Windows x86_64 is Tier 1 for builds, complete functionality, primary numerics, and large-scale release-candidate runs on a fixed qualified host. macOS arm64 receives official CLI and wheel artifacts, clean installation, public API, and representative numerical tests, but does not default to million-scale or Polatory performance comparison. macOS x86_64 leaves the Tier-1 release-blocking set and is optional or unsupported. Hosted jobs fix toolchain, dependencies, target, and OS major version while recording runner-image provenance; exact runner-image build equality across jobs is not required. Experiments that require an identical host stay in one job or on a fixed self-hosted runner.

Performance governance v2 keeps numerical correctness and evidence closure as prerequisites, changes same-host Polatory `1.10x` parity to an optimization target, and sets the initial v1 end-to-end hard ceiling at `1.25x`. Complete user journey and peak memory are the main hard gates; memory retains versioned absolute ceilings and may use separately preregistered route-specific paired ceilings, but v2 does not invent a universal `1.25x` memory ratio. Phase timings, scratch writes, and internal traces are diagnostic or separately preregistered absolute budgets rather than universal non-compensating 10% gates. Reasonable absolute wall-time, memory, scratch, work, thread, and zero-cleanup limits remain hard. Reliability is layered through PR canaries, Nightly 100–300 repetitions, and fixed-host release qualification instead of 3,000 zero-failure trials per platform.

Valid candidate numerical, resource, cancellation, product, timeout, crash, and cleanup outcomes are valid failures and cannot be rerun into success. Runner, network, workflow, artifact, controller, verifier, and equivalent infrastructure failures may receive at most two controlled replacement executions only when candidate, fixture, threshold, and plan are unchanged. Every attempt remains append-only evidence; favorable selection and mixing observations across candidates or plans are forbidden.

Wayfinder issue creation is limited to answers that could change public scope or compatibility, stable API or architecture boundaries, algorithm or backend routes, platform support tiers, release-blocking standards, or irreversible dependency, license, and persistence decisions. Actions workflow defects, path filters, runner images, network or artifact transport, controllers, samplers, verifiers, artifact selectors, filenames, evidence paths, unchanged infrastructure replacement executions, and ordinary implementation defects in an accepted route are normal bugs or tasks. Diagnosis, plan, and bounded execution for one scientific question normally remain in one issue; a successor is justified only by a new specification-changing decision.

This decision supersedes only the conflicting governance in ADR 0004 and Issues 16, 17, and 64: a sole globally winning route, universal `2^-24` iterative gating, universal same-host `1.10x` phase/resource gates, identical four-platform large-scale qualification, 3,000 zero-failure trials per platform, and pre-specification executable-source qualification. It preserves all historical issues and evidence, the strict mathematical semantics and direct-reference ceilings, high-precision oracle hierarchy, complete external residuals, CPD/KKT certificates, transactional failure, candidate-independent calibration, append-only attempts, no observation mixing, and the prohibition on post-hoc threshold or algorithm changes.
