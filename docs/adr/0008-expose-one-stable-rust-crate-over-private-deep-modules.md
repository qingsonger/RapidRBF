# Expose one stable Rust crate over private deep modules

RapidRBF v1 publishes one feature-complete, SemVer-stable `rapidrbf` library crate whose const-generic `D = 1 | 2 | 3`, `f64` domain workflows are organized under `model`, `interpolation`, `kriging`, `geometry`, `artifact`, `execution`, and `error`. The interface uses owned opaque RapidRBF types, synchronous `.run(&Context, CallControl)`, one structured `Outcome<T>` / `Failure` model, explicit process-local `PreparedEvaluator<D>` reuse, and abstract auditable route reports; `CertifiedField` is the only caller-implemented extension seam.

Core orchestration, matrix-kernel actions, solvers, numerics, geometry, formats, concrete routes, backends, caches, plans, and third-party types remain private and start as deep `pub(crate)` modules rather than one crate per concept. Workspace crates are introduced only for real packaging or risk seams such as the CLI, Python extension, a pinned backend fork, or an audited unsafe/platform adapter; the public crate and core orchestration forbid their own unsafe code, and v1 exposes no backend plugin, C ABI, dynamic-dimension object, public Serde state, async runtime binding, capability-cutting Cargo feature, or backend selector.

This concentrates the complete compatibility surface in one interface and one qualification combination while preserving backend replaceability, resource governance, and adapter consistency. It accepts longer module-qualified names, conversion at adapter seams, and fewer user extension points rather than stabilizing shallow internal interfaces or implementation identities. The full decision and rejected alternatives are recorded in [Choose the Rust architecture and stable API boundaries](https://github.com/qingsonger/RapidRBF/issues/20).
