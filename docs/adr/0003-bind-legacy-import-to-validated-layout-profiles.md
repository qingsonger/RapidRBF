# Bind legacy import to validated layout profiles

RapidRBF's one-way importer accepts every valid `Model` and fitted `Interpolant` state expressible by a supported, accepted-ready legacy layout profile, only under an explicit kind, dimension, and profile declaration plus a bounded resource grant; it preserves accepted finite numeric state exactly except for defined domain canonicalization, rebuilds all runtime state, and does not claim the lost historical fit evidence. The importer consumes exactly one artifact, validates its known structure and domain state atomically, and fails through stable request, layout, I/O, malformed-artifact, unsupported-variant, invalid-state, or operational categories without autodetection, fallback parsing, prefix salvage, repair, or refitting. An unknown layout gains direct support only through new frozen profile evidence, while the bounded source-side conversion route may preserve it into a portable artifact; this accepts extra migration tooling in exchange for keeping unsafe native formats and loaders outside RapidRBF's runtime, as decided in [Choose the legacy artifact import boundary and failure semantics](https://github.com/qingsonger/RapidRBF/issues/23).
